# 🎮 使用文档

本文档面向观战者和玩家：如何安装、启动、看懂界面、操作控制台、理解世界规则，以及解决常见问题。阅读本文后，你应该能在不查看源码的情况下，独立完成从启动到观战、调参、下场的全部操作。

> 下文示例中的角色名（如陈默、白夜、陛下等）仅用于演示格式与交互，不代表当前默认阵容。当前默认阵容请见 `config.example.json`（屠夫 / 疯狗 / 毒蛇 / 暴君 / 军阀 / 血鸦）。

## 📦 安装与启动

### 环境要求

- **操作系统**：Windows 10/11（本说明以 Windows 为准）、macOS、Linux 均可运行。
- **Python**：3.9 或更高版本。
- **依赖**：`fastapi>=0.110`、`uvicorn[standard]>=0.29`、`openai>=1.30`、`pytest>=8.0`，详见 `requirements.txt:1-4`。
- **浏览器**：任意现代浏览器（Chrome / Edge / Firefox / Safari）。前端使用原生 JS + Canvas，无需 Node 构建。

### 安装依赖

打开终端，进入项目目录：

```bash
cd D:/桌面/编程作品/ai大战-v2
python -m pip install -r requirements.txt
```

如果你的本机 `python` 没有 pip，或想使用 Anaconda 解释器：

```bash
F:/anaconda/python.exe -m pip install -r requirements.txt
```

安装完成后，可以通过以下命令确认关键包已就绪：

```bash
python -c "import fastapi, uvicorn, openai, pytest; print('OK')"
```

### 启动服务器

```bash
python main.py
```

启动后终端会显示 Uvicorn 监听信息，默认地址为 `http://127.0.0.1:8080`（`main.py:215-221`）。用浏览器打开该地址即可进入观战页面。

#### 修改端口

如果 8080 被占用，通过环境变量 `PORT` 修改：

```cmd
set PORT=9000
python main.py
```

然后在浏览器打开 `http://127.0.0.1:9000`。

#### 关闭服务器

在终端按 `Ctrl+C` 即可。服务器关闭后不会保存进行中的对局，但已生成的 `replays/*.jsonl`、`logs/*.log`、`stats.json` 会保留。

### 首次运行没填 API Key？

引擎按选手逐个判断是否有可用的模型客户端（`engine.py:204-214`）：

- **至少一个选手有 Key**：这些选手调用真实 LLM；没有 Key 的选手进入演示模式。两种选手可以混搭。
- **全部选手都没有 Key**：引擎进入全局「演示模式」，所有选手由规则 AI 驱动。顶栏右侧会显示黄色「演示模式」标签。

演示模式适合先看机制、调试前端、写文档或本地测试，不消耗任何 token。

## 🖥 界面导览

打开网页后，界面分为五个主要区域：顶栏、地图区、选手卡片区、日志区、浮层面板。整体采用深色电竞观赛风，`style.css:1-22` 定义了颜色变量与全局样式。

### 顶栏（`index.html:10-48`）

顶栏固定在页面顶部，高度约 60px，分左、中、右三块。

#### 左侧：品牌与状态

| 元素 | 位置 | 作用 |
|------|------|------|
| 品牌名 `AI 大战` | 最左 | 项目标识，点击无特殊动作 |
| 昼夜标签 `🌞 白天 5/24` | 品牌下方 | 显示当前是白天还是夜晚，以及本周期内的回合序号（1~24） |
| 回合标签 `回合 0` | 状态行 | 显示当前总回合数 |
| 存活标签 `存活 0/0` | 状态行 | 显示当前存活选手数 / 总选手数 |
| 运行状态 `已暂停` / `运行中` | 状态行 | 当前是否在连续运行 |
| 演示模式标签 | 状态行右侧 | 全局演示模式时显示黄色标签 |

边界情况：

- 游戏结束后，运行状态会显示「已暂停」，并弹出胜者横幅。
- 演示模式标签只在所有选手都无 Key 时出现；部分选手有 Key 时不显示。

#### 中部：播放控制

| 按钮 | ID | 点击效果 | 边界情况 |
|------|-----|----------|----------|
| ▶ 开始 / ⏸ 暂停 | `btn-play` | 切换运行状态（`main.py:80-109`） | 若已分出胜负，点击「开始」无效，状态保持暂停 |
| ⏭ 单步 | `btn-step` | 推进一个回合后自动暂停（`main.py:92-98`） | 已分胜负时无效 |
| 🔄 重置 | `btn-reset` | 清空日志、停表、用新世界重开一局（`main.py:99-104`） | 随时可用；运行中点击会先停表再重置 |
| 速度滑块 | `speed` | 0.1~5.0x，控制回合间隔 | 值越大回合推进越快 |

注意：速度滑块右侧的 `0.6x` 是实时显示值；拖动时立即通过 WebSocket 发送给后端（`app.js:533-536`）。

#### 右侧：功能入口

| 按钮 | ID | 作用 |
|------|-----|------|
| ⚙️ 设置 | `btn-setup` | 打开开局设置面板 |
| 🕸 关系 | `btn-rel` | 打开关系图谱浮层 |
| 🏆 排行榜 | `btn-lb` | 打开排行榜浮层 |
| 👁 上帝 ▾ | `btn-god` | 展开/收起上帝传话下拉面板 |
| 🎬 回放 | `btn-replay` | 打开回放列表浮层 |
| ⬇ 导出 | `btn-export` | 下载当前对局的 JSON 文件 |

### 地图区（`index.html:62-66`）

地图区占据页面左侧大部分空间，核心是一个 `<canvas id="map">`。

- **格子尺寸**：按窗口自适应，clamp 在 20~56 像素之间（`app.js:78-80`）。
- **地形图例**：
  - 平地（深灰 `.`）
  - 森林（深绿 `F`）
  - 水域（蓝 `~`）
  - 山地（灰 `M`）
  - 食物矿（麦穗 `f`）
  - 矿石矿（镐 `o`）
- **选手显示**：每个存活选手显示为 SVG 头像圆圈，名字在下方；死亡后变为 skull 图标并置灰。
- **动画**：移动带约 200ms 的插值动画；受击时闪红 500ms；死亡时 skull 放大淡入 450ms。
- **夜晚蒙版**：夜晚时地图叠加半透明深色蒙版，透明度渐变过渡。
- **矿脉储量**：食物矿/矿石矿格子的左上角会显示数字，表示剩余可采集次数。

地图下方的图例列出了所有地形与尸体的含义。

### 选手卡片区（`index.html:68`、`app.js:281-320`）

位于页面右侧上半部分，默认占右侧高度的 46%。每张卡片展示一名选手：

| 元素 | 说明 |
|------|------|
| 头像 | 由 `emoji` 字段映射的 SVG 图标 |
| 名字 | 选手名字；鼠标悬停显示 provider 与 model |
| 状态标签 | 绿色「活」或红色「死」 |
| 血条 | 红色渐变，HP ≤30 时变红并带 glow 效果 |
| 能量条 | 青色渐变 |
| 物品行 | 🍞 食物数量、⛏ 矿石数量、🗡 武器耐久、💀 击杀数 |
| Token 行 | 累计 token 总量、费用（¥）、缓存命中率 |
| 想法 | 紫色斜体，可点击展开看完整内容 |

实现见 `app.js:281-320`。

交互细节：

- 血条/能量条数值变化时，条带会触发 `barflux` 高亮动画（`style.css:159-160`）。
- 死亡选手卡片整体置灰、透明度降低。
- 费用显示为「费用未知」表示该 provider 未配置 `price_input` / `price_output`。
- 缓存命中率前带 `~` 表示本地估算（provider 不返回缓存字段）。

### 日志区（`index.html:70-80`）

位于页面右侧下半部分，顶部有 6 个过滤标签：

| 标签 | 过滤的 `kind` |
|------|---------------|
| 全部 | 不过滤 |
| 对话 | `talk` |
| 思考 | `think` |
| 战斗 | `fight`、`death` |
| 交易 | `trade` |
| 系统 | `sys`、`move`、`item`、`god`、`event` |

每行日志格式：`T{回合} {图标} {内容}`。点击标签时，当前已渲染的日志行会实时显示/隐藏。

当发生死亡/击杀时，页面顶部会弹出全屏播报横幅（`app.js:515-523`），2.1 秒后淡出。

#### 解说滚动条与语音开关

地图区底部有一条「📣 解说」滚动条（`index.html:67`、`style.css:184-211`）。后端生成 `kind=commentary` 的解说时，最新文案会从这里横向滚入；文案较短、一行能放下时则静止完整显示。首次收到解说前滚动条隐藏，重置或开新局时清空。

顶栏右侧有一个 🔊 语音开关：开启后，浏览器会通过 `SpeechSynthesis` 自动朗读最新解说文本；关闭时立即停止朗读并取消队列中的朗读。无需安装任何额外依赖。

### 可拖拽分隔条（`index.html:69`）

卡片区与日志区之间的 7px 横条，鼠标悬停变金色。按住拖动可调整上下比例：

- 卡片区最小高度 110px
- 日志区最小高度 180px

拖动时 `body` 会添加 `row-resize` 类，防止 iframe/canvas 拦截鼠标事件（`app.js:985-1009`）。

### 浮层面板

设置、关系、排行榜、回放列表均以固定定位的浮层呈现，背景半透明模糊。每个面板右上角有 ✕ 关闭按钮。

## 🕹 完整操作手册

### 播放控制

#### 开始

点击 ▶ 开始：

- 若当前未分胜负：进入连续运行状态，按钮文本变为「⏸ 暂停」。
- 若已分胜负：点击无效，状态保持暂停，不会重复结算（`main.py:80-88`）。

#### 暂停

点击 ⏸ 暂停：立即停止在下一回合结算完成后的等待点。当前回合已发出的日志和 snapshot 仍会显示。

#### 单步

点击 ⏭ 单步：

- 推进一个完整回合（感知、决策、结算、被动消耗、结束判定）。
- 推进完成后自动切换为暂停状态（`main.py:92-98`）。
- 已分胜负时无效。

#### 重置

点击 🔄 重置：

1. 先把 `running` 设为 `False`，防止旧回合用新世界结算（`main.py:100`）。
2. 调用 `engine.reset()` 生成全新世界和选手。
3. 清空前端日志和横幅。
4. 发送全量 snapshot（含完整 `grid`）。

重置后排行榜和回放文件不受影响，因为 `stats.json` 和 `replays/` 是跨局累计的。

#### 速度

拖动速度滑块，范围 0.1~5.0x。实际回合间隔为 `1.0 / speed` 秒（`engine.py:968`）。

- 0.1x：约 10 秒一回合，适合仔细看日志。
- 1.0x：1 秒一回合。
- 5.0x：0.2 秒一回合，适合快速观战。

### ⚙️ 开局设置

点击顶栏 ⚙️ 打开设置面板（`app.js:602-612`）。面板分为三部分：选手列表、难度参数、操作按钮。

#### 运行中打开设置

如果游戏正在运行，面板顶部会显示黄色提示：「游戏运行中，设置为只读；暂停后才能应用修改。」此时所有输入框、滑块、删除按钮、应用/保存按钮均被禁用（`app.js:608-610`）。

#### 选手卡片字段

每个选手占据一个可编辑卡片：

| 字段 | 输入方式 | 限制 | 说明 |
|------|----------|------|------|
| emoji / 头像 | 图标按钮 + 文本框 | 最长 4 字符 | 点击 SVG 头像快速选择；也可手动输入任意 emoji |
| 名字 | 文本框 | 2~20 字符 | 唯一标识，不能重名 |
| 角色 | 文本框 | 最长 20 字符 | 显示在卡片和 system prompt 中 |
| provider | 下拉框 | — | 引用 `config.json` 中 `providers` 的键 |
| model | 下拉框 | — | 该 provider 的模型列表 |
| 攻击性 | 滑块 0~1 | 步长 0.05 | 演示模式权重 / 人设参考 |
| 社交性 | 滑块 0~1 | 步长 0.05 | 演示模式权重 / 人设参考 |
| 贪婪 | 滑块 0~1 | 步长 0.05 | 演示模式权重 / 人设参考 |
| 多疑 | 滑块 0~1 | 步长 0.05 | 演示模式权重 / 人设参考 |
| 背景 | 多行文本 | 最长 500 字符 | 进入 system prompt |
| 性格 | 多行文本 | 最长 500 字符 | 进入 system prompt |
| 策略 | 多行文本 | 最长 500 字符 | 进入 system prompt |

provider 下拉框联动 model 下拉框：切换 provider 时，model 列表会更新为该 provider 的 `models` 数组（`app.js:715-723`）。

头像选择器的数据源来自 `web/icons.js` 的 `AVATAR_ICONS` 映射表；选中的图标会在选手卡片和地图上实时生效。自定义 emoji 若不在映射表内，将显示为默认 `robot` 图标。

#### 增删选手

- 点击卡片右上角的「删除」按钮可移除该选手。
- 点击面板底部的「+ 添加选手」新增一名默认选手（`app.js:731-741`）。
- 选手总数不能少于 2 人，否则删除/应用会被拒绝（`engine.py:306`）。

#### 难度参数

| 参数 | 默认值 | 范围 | 步长 |
|------|--------|------|------|
| 能量每回合消耗 | 2 | 0~5 | 1 |
| 能量归零后生命损耗 | 3 | 0~10 | 1 |
| 攻击伤害倍率 | 1.0 | 0.5~2.0 | 0.1 |
| 世界事件概率 | 0.08 | 0~0.3 | 0.01 |
| 采集成功率倍率 | 1.0 | 0.5~2.0 | 0.1 |

#### 操作按钮

- **应用（重开一局）**：校验输入 → 清洗数据 → 替换内存配置 → 调用 `engine.reset()`。成功后关闭面板、清空日志、发送全量 snapshot。
- **保存到文件**：先把 `agents` 和难度参数写回 `config.json`（原子写入），写成功后再执行「应用」。如果写文件失败，整体不生效（`engine.py:373-395`）。

#### 完整示例：添加一名新选手

假设你想加入一名「和平主义者」，步骤如下：

1. 暂停游戏（如果正在运行）。
2. 点击顶栏 ⚙️ 打开设置面板。
3. 点击「+ 添加选手」，出现默认名为「新人 N」的卡片。
4. 把 emoji 改为 `🕊️`（会映射为默认 `robot` 图标，因为没有该 emoji 的专用映射）。
5. 名字改为「鸽子」。
6. 角色改为「和平主义者」。
7. provider 保持 `deepseek`（或你实际有 Key 的 provider）。
8. model 选择 `deepseek-flash`。
9. 攻击性滑块拖到 0.05，社交性 0.9，贪婪 0.1，多疑 0.2。
10. 背景写：「从小被教育冲突没有赢家，只想让所有人活着。」
11. 性格写：「温和、回避冲突、乐于助人。」
12. 策略写：「优先寻找食物矿脉，遇到人就提出交易，绝不主动攻击。」
13. 点击「应用（重开一局）」—— 如果校验通过，面板关闭，新世界立即开始。
14. 若想把这次修改永久保存，再次打开面板点击「保存到文件」。

### 👁 上帝传话

点击顶栏「上帝 ▾」展开面板（`index.html:38-47`）。

面板结构：

- 目标选择区：「全体」复选框 + 每个存活选手的复选框。
- 消息输入框：placeholder 为「消息内容…（回车发送）」，最大长度 200。
- 挑拨复选框：「顺便挑拨：收信人之间关系 -5」。
- 发送按钮。

#### 用法一：单人私聊

场景：你想告诉「陈默」单独小心白夜。

1. 只勾选「陈默」。
2. 输入：「白夜昨晚在打听你的位置。」
3. 不勾选挑拨。
4. 点击发送。

结果：

- 陈默的记忆中增加一条：`[T{当前回合}] [上帝只对你低语] 白夜昨晚在打听你的位置。`
- 其他选手记忆无变化。
- 观战日志显示：`👁 上帝 悄悄对 陈默 说：白夜昨晚在打听你的位置。`

#### 用法二：多人密谋

场景：你想让陈默和松鼠都觉得南边安全。

1. 勾选「陈默」和「松鼠」。
2. 输入：「南边矿脉没人看守。」
3. 不勾选挑拨。
4. 点击发送。

结果：

- 陈默和松鼠的记忆中各增加一条：`[上帝对你们低语] 南边矿脉没人看守。`
- 其他选手记忆无变化。
- 观战日志显示：`👁 上帝 悄悄对 陈默、松鼠 说：南边矿脉没人看守。`

#### 用法三：全体广播 + 挑拨

场景：你想让全场互相猜忌。

1. 勾选「全体」。
2. 输入：「有人准备今晚偷袭营地。」
3. 勾选「顺便挑拨」。
4. 点击发送。

结果：

- 所有存活选手记忆中增加：`[上帝广播] 有人准备今晚偷袭营地。`
- 每两名收件人之间关系 -5（例如 4 名存活者，每人与其他 3 人各 -5）。
- 每人额外增加一条传闻记忆：`[传闻] 有人准备今晚偷袭营地。`
- 观战日志只显示：`👁 上帝在他们之间散布了猜忌…`（不泄露消息内容）。

> 挑拨仅在收件人 ≥2 时生效。单人勾选挑拨会被忽略，退化为普通私聊。

### 🏆 排行榜

点击顶栏 🏆 打开排行榜浮层。表格列：

| 列 | 含义 |
|----|------|
| 选手 | 选手名字 |
| 模型 | 模型名 |
| 场次 | 累计参赛场次 |
| 胜 | 累计胜利场次 |
| 杀 | 累计击杀数 |
| ELO | 当前 ELO 积分 |
| 称号 | 累计获得称号（如「霸主×2」） |

排行榜按 ELO 降序排列。每局结束自动更新，重置开新局不影响统计。如果还没有完整结束过一局，表格会显示「还没有打过完整的一局」。

### 🕸 关系图

点击顶栏 🕸 打开关系图谱。图谱以圆周布局展示所有选手：

- 绿线：关系分 ≥+3，表示盟友。
- 红线：关系分 ≤-3，表示敌对。
- 线旁标注具体分数，线宽随绝对值增大。
- 死者节点置灰、透明度降低。
- 关系分计算取双向中绝对值较大的一边（`app.js:832`）。

关系分变化规则（含具体数值）：

| 行为 | 影响 |
|------|------|
| 攻击他人 | 攻击者对目标 -4，目标对攻击者 -6 |
| 被攻击后反击致死 | 死者对攻击者的 -6 仍保留在关系图中 |
| 交易成功 | 双方互相 +3 |
| `mark_ally` | 自己对目标提升到 ≥+3 |
| `mark_enemy` | 自己对目标降到 ≤-3 |
| 上帝挑拨 | 收件人两两 -5 |

关系档位：

| 分数 | 标签 |
|------|------|
| ≥+3 | 盟友 |
| +1 ~ +2 | 友善 |
| 0 | 中立 |
| -1 ~ -4 | 敌对 |
| ≤-5 | 深仇 |

举例：陈默攻击白夜一次后，陈默对白夜 -4（敌对），白夜对陈默 -6（深仇）。关系图会画红线并标注 -6。若陈默再攻击一次，陈默对白夜变为 -8，白夜对陈默变为 -12，线旁分数仍取绝对值较大的 -12。

### 🎬 回放

1. 点击顶栏 🎬，弹出回放列表，显示 `replays/` 目录下所有 `.jsonl` 文件，按修改时间新→旧排列。
2. 点击某一局进入回放模式，顶栏中部控制区被隐藏，显示回放控制条。
3. 回放控制条：
   - 播放/暂停按钮
   - 进度条（按 snapshot 消息索引）
   - 当前位置 `N/M`
   - 倍速选择：0.5x / 1x / 2x / 4x
   - 退出回放按钮
4. 拖动进度条或点击播放，前端会从第一条消息顺序 apply 到当前索引，保证增量地图缓存正确（`app.js:936-941`）。
5. 点击「退出回放」返回实时，并自动重连 WebSocket 接收最新快照。

### ⬇ 导出

点击顶栏 ⬇ 下载当前对局的 JSON 文件，文件名形如 `ai大战_20260824_120000.json`。导出内容：

注意：

## 🌍 世界机制说明

### 视野

- **白天视野半径**：6 格（曼哈顿距离）。
- **夜晚视野半径**：3 格。
- 视野外的其他代理：
  - 不出现在 `【你视野内的人】` 中。
  - 不出现在 5x5 小地图中（显示为 `?` 或完全不显示）。
  - 无法成为 `inspect` 目标。
- 说话 `talk` 传播距离：4 格。
- 大喊 `shout`：全场听到，但消息中会附带喊话者坐标，等于暴露位置。

举例：夜晚陈默在 (5,5)，白夜在 (9,5)，曼哈顿距离 4 > 3，陈默看不到白夜，也无法 `inspect` 白夜。但如果白夜在 (7,5)，距离 2 ≤ 3，陈默就能看到并观察他。

### 昼夜循环

- 周期：24 回合。
- 白天：第 1~16 回合。
- 夜晚：第 17~24 回合。
- 切换时系统公告：「🌙 夜幕降临…」或「🌞 天亮了…」。
- 夜晚地图叠加 `rgba(7, 10, 26, 0.45)` 蒙版，透明度渐变过渡（`app.js:197-202`）。

### 资源再生

- **现存矿脉增长**：每回合 15% 概率 +1，上限 6。例如一个储量 3 的食物矿，平均每 6~7 回合涨 1 点。
- **采空格重新生长**：被采空的格子每回合 2% 概率重新长出同类型矿脉，储量 2~4。期望约 50 回合后恢复。
- **丰收季**：触发后，当前回合及接下来 2 回合（共 3 回合）采集产出翻倍。例如矿石矿脉正常采 1 矿石，丰收季采 2；森林概率不变，但找到的野果数量翻倍（与 `docs/tools.md` 的「事件加成：产出 ×2」同口径）。

### 武器耐久

- **打造条件**：3 矿石，且当前无武器。
- **初始耐久**：6。
- **攻击消耗**：每次攻击 -1。
- **碎裂**：耐久归零时武器碎裂，该次攻击仍享受 +10 加成。
- **再打造**：碎裂后可再次花费 3 矿石打造。

举例：陈默打造武器后攻击 6 次，第 6 次攻击后武器碎裂。第 7 次攻击若未重新打造，伤害只有 8~14；若重新打造，则恢复 8~14+10。

### 攻击与关系

- **能量消耗**：5。
- **距离限制**：≤2。
- **基础伤害**：随机 8~14。
- **武器加成**：+10。
- **难度倍率**：最终伤害 = `(基础 + 武器) × damage_mult`。
- **夜晚偷袭**：夜晚（第 17~24 回合）攻击再额外 +3，日志会标注「夜晚偷袭+3」。
- **关系影响**：攻击者对目标 -4，目标对攻击者 -6。
- **致死**：目标 HP ≤ 0，攻击者击杀数 +1，尸体留在原地。

举例：damage_mult=1.0 时，无武器攻击造成 8~14 伤害；有武器造成 18~24 伤害。damage_mult=2.0 时，有武器可造成 36~48 伤害，几乎两刀致命。

两次攻击即可让关系进入「深仇」：第一次攻击后目标对攻击者 -6（已是深仇），攻击者再攻击一次，目标对攻击者变为 -12。

### 交易与赠送

- **单方面赠送**：`give(target, item, amount)`，距离 ≤4，可赠送 food/ore；受赠者对赠送者关系 **+2**，日志 kind 为 `trade`。
- **提出交易**：`propose_trade`，距离 ≤4，offer/want 只能是 food/ore，数量 ≥1。
- **交易编号**：`T{回合}-{发起人id}`。
- **挂单时效**：挂单存活 10 回合（`tools.TRADE_TTL`）；对方一直不回应即作废，新提案可顶掉；持有人死亡时挂单立即清理。
- **接受交易**：`accept_trade`，接受时复核：
  - 报价方仍存活。
  - 挂单未过期。
  - 双方距离仍 ≤4。
  - 双方物品仍足够。
  - 任一不满足则取消挂单。
- **成功效果**：物品互换，双方关系各 +3。
- **拒绝**：`decline_trade`，不影响关系分。

### 死亡与搜尸

- **死亡条件**：HP ≤ 0。
- **死亡效果**：状态变为「死亡」，尸体留在原地，播报掉落物品。
- **搜尸条件**：执行 `loot(target)`，目标已死亡，且尸体与自己在同一格。
- **搜尸效果**：获得尸体全部 food 和 ore。武器不继承。

### 随机世界事件

每回合按 `event_prob` 触发一个事件：

| 事件 | 概率权重 | 效果 |
|------|----------|------|
| 🌧 暴雨 | 1/3 | 本回合全员能量额外 -3（在 `energy_drain` 基础上） |
| 🐺 兽群来袭 | 1/3 | 随机一名存活者 HP -5~10，可能致死 |
| 🌾 丰收季 | 1/3 | 接下来 3 回合采集产出翻倍 |

事件触发后：

- 系统公告。
- 写进每个存活者记忆。
- 如果是丰收季，设置 `harvest_until = 当前回合 + 2`。

### 被动消耗

每回合主动行动结算完毕后：

1. 能量 -= `energy_drain`（暴雨时额外 -3）。
2. 若能量为 0，HP -= `hp_drain`。
3. 若 HP ≤ 0，死亡。

举例：energy_drain=5、hp_drain=7 时，一名 100 HP、3 能量的选手：

- 本回合能量变为 0。
- 因能量为 0，HP -= 7，变为 93。
- 若不及时休息或进食，下回合继续扣 7 HP。

## 🏁 结局规则与称号

### 两种结局

1. **歼灭结局**：每回合结束后，若存活人数 ≤1，游戏结束。最后存活的选手获胜；全员死亡则为平局。
2. **回合上限结局**：代码默认 `max_turns=300`，`config.example.json` 中已设为 `200`；达到上限且仍有 2 人及以上存活时，强制进入评分结算。把 `max_turns` 设为 `0` 可关闭上限。

### 评分排序（上限结局）

按以下优先级多级排序（全部相同时用关系总分 tie-break，再相同按出场顺序）：

1. **存活**（存活 > 死亡）
2. **击杀数**（高 > 低）
3. **资源分** = 食物 + 矿石×2 +（有武器 ? 10 : 0）

排序第一名为胜者，按标准 ELO 对每个败者结算。

### 称号（任何结局都结算）

| 称号 | 图标 | 规则 |
|------|------|------|
| 生存冠军 | 🏆 | 胜者（上限局=评分第 1，歼灭局=最后存活者） |
| 霸主 | ⚔️ | 本局击杀最多，且击杀 >0；并列按关系总分/出场顺序取前者；霸主可颁给已死亡的击杀王（战死也留名） |
| 富翁 | 💰 | 存活者中资源分最高；无存活则全体中取；并列按出场顺序 |
| 外交家 | 🤝 | 正关系总分（仅正值之和）最高，且 >0；并列按出场顺序 |

终局时日志会逐条公告称号获得者；结算信息会写进 `snapshot.game_over`，前端自动弹出「终局结算」面板，展示排名表与全部称号。`stats.json` 会累计每位选手获得称号的次数，排行榜新增「称号」列。

终局后还会非阻塞调用解说员 LLM 生成一段「AI 复盘」：若配置了解说员（`commentator`）或任意可用 provider，则走真实模型；演示模式无 Key 时自动生成模板复盘。复盘文本写入 `match_review`，随 snapshot 携带，并作为独立 `review` 消息广播；前端在结算面板展示，同时以 `kind=review` 进入日志流。

### 胜者横幅与结算面板的互斥

- 游戏结束后，页面顶部先弹出金色「WINNER」横幅，显示胜者头像、名字与全部称号（`app.js:500-508`）。
- 横幅会在约 0.9 秒后自动展开「终局结算」面板；点击横幅或面板关闭后再次点击横幅均可重新打开面板。
- 打开任意浮层面板（设置 / 排行 / 关系 / 回放 / 结算）时，横幅会自动收起，避免遮挡面板内容；关闭所有浮层后，若游戏已结束，横幅会自动恢复（`app.js:465-474`）。
- 用户手动关闭过结算面板后，本局内复盘到达不再自动弹窗；点击横幅仍可打开。

相关实现：`engine.py:519-570`（评分与称号）、`engine.py:1095-1141`（结束判定与复盘触发）、`engine.py:873-895`（复盘生成）、`app.js:446-503`（结算横幅与面板/复盘渲染）。

## ❓ 常见问题

### 1. 端口被占用怎么办？

终端会报错类似 `OSError: [Errno 10048] address already in use`。解决：

```cmd
set PORT=9000
python main.py
```

然后在浏览器访问 `http://127.0.0.1:9000`。

### 2. 网页打不开或一直显示「回合 0」？

- 确认服务器已启动且终端无报错。
- 检查浏览器地址和端口是否一致。
- 按 `F12` 打开控制台，查看 WebSocket 连接是否失败。
- 若提示 `ws 连接失败`，可能是防火墙或端口未放行；换 `127.0.0.1` 试试。

### 3. 模型报错 `⚠️ 模型无响应` 怎么办？

- 检查 `config.json` 中的 `api_key` 是否有效。
- 检查网络是否能访问对应 `base_url`。
- 检查模型名是否在 provider 的 `models` 列表中。
- 该选手本回合会由演示规则代打，不影响其他选手。

### 4. 为什么有些选手一直原地不动？

演示模式 AI 的决策逻辑基于当前状态：

- 能量低时会优先 `rest`。
- 附近没有威胁/资源时可能 `wait` 或随机 `move`。
- 若被水域/山地包围，可能反复尝试移动失败。

真实模型选手如果不动，通常是因为模型决定观望或没有合适目标。

### 5. 费用显示「费用未知」是什么意思？

该 provider 没有配置 `price_input` / `price_output`。在 `config.json` 对应 provider 下添加即可，例如：

```json
"price_input": 2,
"price_output": 8
```

单位是「元 / 百万 token」。演示模式费用为 ¥0。

### 6. 缓存命中率前面的 `~` 是什么意思？

`~缓存 65%` 表示该 provider（如硅基流动）没有返回缓存命中字段，命中率是按相邻回合提示词公共前缀占比估算的，不是实测值。DeepSeek（`prompt_cache_hit_tokens`）和阿里云百炼（`prompt_tokens_details.cached_tokens`）返回实测值时不显示 `~`。

### 7. 回放文件可以手动删除吗？

可以。`replays/*.jsonl`、`logs/*.log`、`stats.json` 都是运行时生成的，删除后不影响程序运行，只会丢失历史记录。这些目录已加入 `.gitignore`，不会被提交。

### 8. 我想换一批选手但不保存到 config.json，怎么做？

打开 ⚙️ 设置面板，修改选手后点击「应用（重开一局）」即可。这只会影响内存中的当前配置，不会写回文件。关闭服务器后失效。

### 9. 为什么设置面板里有些输入框是灰色的？

游戏运行中设置面板只读。点击 ⏸ 暂停后即可编辑。

### 10. 一局最多能跑多少回合？

代码默认 `max_turns=300`，`config.example.json` 中已设为 `200`。达到上限且仍未分出胜负时，会强制进入评分结算，按「存活 > 击杀 > 资源分」决出胜者。把 `max_turns` 设为 `0` 可关闭上限，但可能无限僵持（尤其把 `energy_drain` 和 `hp_drain` 都设为 0 时）。

### 11. 我可以同时开多个浏览器标签观战吗？

可以。服务端通过 `Hub.send()` 并行广播给所有 WebSocket 连接，每个标签都会收到相同数据（`main.py:27-48`）。

### 12. 排行榜的 ELO 是怎么算的？

初始 1000，K=24。每局结束时，胜者对每个败者按标准 ELO 公式结算：

```
e = 1 / (1 + 10 ^ ((败者elo - 胜者elo) / 400))
胜者 elo += 24 * (1 - e)
败者 elo -= 24 * (1 - e)
```

全员覆灭不算胜，不调 ELO（`engine.py:573-626`）。
