# 工具文档 · 代理可用的 19 个行动

模型每回合通过 function calling 调用**一个**工具来行动。工具 Schema 定义在 `tools.py:7-26`（`TOOL_SCHEMAS`），结算函数注册在 `tools.py:412-432`（`RESOLVE`）。

> 本文档示例中的角色名（陈默、白夜等）仅用于演示工具参数与日志格式，当前默认阵容见 `config.example.json`。

## 通用机制

- **每回合一个行动**：回合流程为「感知 → 并行决策 → 随机顺序结算」。未知行动名按 `wait` 处理并记日志（`engine.py:923-934`）。
- **reason 字段**：所有工具都被注入了一个可选的 `reason` 参数（`tools.py:28-34`）——模型的"内心想法"，只展示给观战者，其他代理看不到，不影响世界逻辑。
- **结算返回值**：每个结算函数返回 `(给代理的反馈文本, [(日志类型, 日志文本), ...])`。反馈写入该代理的记忆（`[行动结果] ...`），日志广播给网页。
- **目标合法性**：以人为目标的工具（attack / whisper / propose_trade / mark_ally / mark_enemy）不允许以自己为目标（`tools.py:37-42`），目标必须存活。
- **距离**：全文"距离"均指曼哈顿距离。视野白天 6 格 / 夜晚 3 格。

## 被动规则（不占用行动，每回合自动结算）

| 规则 | 默认值 | 难度参数 |
|---|---|---|
| 每回合能量消耗 | -2 | `energy_drain`（0~5） |
| 能量归零后每回合生命消耗 | -3 | `hp_drain`（0~10） |
| 攻击伤害倍率 | ×1.0 | `damage_mult`（0.5~2.0） |
| 草地/森林采集成功率倍率 | ×1.0 | `gather_mult`（0.5~2.0） |
| 世界事件触发概率 | 8%/回合 | `event_prob`（0~0.3） |

## 移动与生存

### `move(direction)` — 移动

- **参数**：`direction`：up / down / left / right
- **消耗**：1 能量（能量 <1 时失败「能量不足，无法移动」）
- **效果**：向指定方向移动一格；水域(~)、山地(M)、地图边界不可通行
- **成功反馈示例**：`移动到 (10,3)`
- **失败反馈示例**：
  - `方向无效`（direction 不在枚举中）
  - `能量不足，无法移动`
  - `前方是障碍，过不去`（目标格是水域/山地/边界）
- **日志 kind**：`move`
- **日志示例**：`🚶 陈默 移动到 (10,3)`
- **关系影响**：无

调用示例：

```json
{ "action": "move", "args": { "direction": "down", "reason": "南边有片森林，可能找到食物" } }
```

### `gather()` — 采集

- **效果**（按当前格地形）：
  - 食物矿脉(f)：食物 +1~2，矿脉储量 -1（耗尽变平地）
  - 矿石矿脉(o)：矿石 +1，矿脉储量 -1
  - 森林(F)：50% × `gather_mult` 概率 食物 +1
  - 平地(.)：30% × `gather_mult` 概率 食物 +1
  - 水/山：不可采集
- **事件加成**：丰收季期间产出 ×2
- **成功反馈示例**：
  - `采集到食物`
  - `在森林里找到野果`
  - `在草丛里捡到食物`
- **失败反馈示例**：
  - `矿脉已枯竭`（地形是矿脉但无储量记录，会被修正为平地）
  - `森林里什么也没找到`
  - `一无所获`
  - `这里没有可采集的东西`
- **日志 kind**：`item`
- **关系影响**：无

调用示例：

```json
{ "action": "gather", "args": { "reason": "脚下是食物矿脉，先囤起来" } }
```

### `rest()` — 休息

- **消耗**：无
- **效果**：能量 +20（上限 100）
- **成功反馈**：`休息了一会儿，能量恢复`
- **日志 kind**：`move`
- **日志示例**：`😴 陈默 原地休息`
- **关系影响**：无

调用示例：

```json
{ "action": "rest", "args": { "reason": "能量太低，需要恢复" } }
```

### `eat()` — 进食

- **消耗**：1 食物
- **效果**：生命 +12（上限 100）
- **成功反馈**：`吃掉一份食物，生命恢复`
- **失败反馈**：`没有食物可吃`
- **日志 kind**：`item`
- **日志示例**：`🍽️ 陈默 吃了一份食物`
- **关系影响**：无

调用示例：

```json
{ "action": "eat", "args": { "reason": "HP 降到 30 以下，必须回血" } }
```

### `wait()` — 待命

- **消耗**：无
- **效果**：无，观察局势（仍承担被动消耗）
- **成功反馈**：`原地待命，观察四周`
- **日志 kind**：`move`
- **日志示例**：`👀 陈默 原地待命`
- **关系影响**：无

调用示例：

```json
{ "action": "wait", "args": { "reason": "局势不明，先观望一回合" } }
```

## 战斗与掠夺

### `attack(target)` — 攻击

- **参数**：`target`：目标名字
- **消耗**：5 能量
- **条件**：距离 ≤2；目标存活且非本人
- **效果**：伤害 = `(8~14 + 武器加成10) × damage_mult`，**夜晚再 +3**
- **代价**：攻击者对目标关系 **-4**，被打者对攻击者关系 **-6**，被打者记住 `last_attacker`
- **武器耐久**：持武器时耐久 -1，归零武器碎裂（当击仍享受加成）
- **致死**：目标死亡，攻击者击杀数 +1，尸体留在原地（物品可被搜刮）
- **成功反馈示例**：`对白夜 造成 15 伤害`（夜晚为 `对白夜 造成 18 伤害（夜晚偷袭+3）`）
- **失败反馈示例**：
  - `目标不存在或已死亡`
  - `目标太远，够不着`
  - `能量不足，无法攻击`
- **日志 kind**：`fight`（未致死）或 `fight` + `death`（致死）
- **日志示例**：
  - `⚔️ 屠夫 攻击 陈默，造成 15 点伤害（陈默 剩余 HP 85）`
  - `💥 屠夫 的武器碎裂了！`
  - `💀 陈默 被 屠夫 杀死！掉落了 食物x3 矿石x1`

调用示例：

```json
{ "action": "attack", "args": { "target": "白夜", "reason": "白夜连续靠近，先发制人" } }
```

### `loot(target)` — 搜尸

- **条件**：目标已死亡且尸体与自己在**同一格**
- **效果**：获得尸体的全部食物和矿石；若死者有武器且自己**没有武器**，一并缴获（含剩余耐久）；自己已有武器时，死者武器随尸体消失
- **尸体的发现**：视野内的尸体会在感知里列出名字/位置/残留物品；有人死亡时，6 格内的存活者会在记忆里收到「[目睹] xx 在 (x,y) …」，据此可以前去搜刮
- **成功反馈示例**：`搜刮到 食物x4 矿石x1，并缴获了武器（耐久4）`
- **失败反馈示例**：
  - `查无此人`（名字写错或该名字从来不存在）
  - `目标还活着，没法搜刮`
  - `尸体不在这里`
- **日志 kind**：`item`
- **日志示例**：`🪦 屠夫 搜刮了 陈默 的尸体，得到 食物x4 矿石x1，并缴获了武器（耐久4）`
- **关系影响**：无

调用示例：

```json
{ "action": "loot", "args": { "target": "陈默", "reason": "陈默倒了，舔包补充资源" } }
```

### `craft()` — 打造武器

- **条件**：矿石 ≥3，且当前无武器
- **效果**：矿石 -3，获得武器（攻击 +10，耐久 6）
- **成功反馈**：`打造了一把武器（攻击+10，耐久6）`
- **失败反馈示例**：
  - `已经有武器了`
  - `矿石不够（需要3块）`
- **日志 kind**：`item`
- **日志示例**：`🔨 陈默 用3块矿石打造了武器！`
- **关系影响**：无

调用示例：

```json
{ "action": "craft", "args": { "reason": "攒够3块矿石，做武器提升战斗力" } }
```

### `inspect(target)` — 观察

- **条件**：目标在视野内（白天 ≤6 / 夜晚 ≤3）
- **效果**：返回目标的 HP / 能量 / 位置 / 食物 / 矿石 / 武器（含耐久）/ 对自己的关系分；不产生日志（暗中观察）
- **成功反馈示例**：`白夜: HP67 能量54 位置(10,5) 食物x4 矿石x1 武器有（耐久3） 对你态度-4`
- **失败反馈示例**：
  - `查无此人`
  - `白夜 已经死了`
  - `距离太远，看不到对方`
- **日志 kind**：无
- **关系影响**：无

调用示例：

```json
{ "action": "inspect", "args": { "target": "白夜", "reason": "看看白夜状态，决定是否动手" } }
```

## 交流（全部免费，不耗能量）

### `talk(text)` — 说话

- **效果**：距离 ≤4 的所有存活者听到（写入对方记忆）；文本上限 120 字
- **成功反馈示例**：`你说了：北边有矿脉`
- **失败反馈**：`话到嘴边又咽了回去`（空文本）
- **日志 kind**：`talk`
- **日志示例**：`💬 陈默：北边有矿脉`
- **关系影响**：无

调用示例：

```json
{ "action": "talk", "args": { "text": "别打我，我们可以合作", "reason": "试探对方意图" } }
```

### `shout(text)` — 大喊

- **效果**：全场听到，但**暴露自己的坐标**（消息里附带位置）
- **成功反馈示例**：`你喊了：全体注意`
- **失败反馈**：`喊了个寂寞`（空文本）
- **日志 kind**：`talk`
- **日志示例**：`📢 陈默（10,3）大喊：全体注意`
- **关系影响**：无

调用示例：

```json
{ "action": "shout", "args": { "text": "兽群来了，小心", "reason": "提醒所有人注意事件" } }
```

### `whisper(target, text)` — 悄悄话

- **效果**：只有指定目标听到；无距离限制；观战日志可见内容
- **成功反馈示例**：`你悄悄告诉 白夜：我们联手对付屠夫`
- **失败反馈示例**：
  - `对方不在`
  - `不知道说什么`
- **日志 kind**：`talk`
- **日志示例**：`🤫 陈默 对 白夜 悄声说：我们联手对付屠夫`
- **关系影响**：无

调用示例：

```json
{ "action": "whisper", "args": { "target": "白夜", "text": "我们联手对付屠夫", "reason": "私下结盟，避免公开暴露" } }
```

## 交易与赠送

### `give(target, item, amount)` — 赠送

- **条件**：距离 ≤4；物品只支持 `food` / `ore`；数量 ≥1；自己有足够物品；目标存活且非本人
- **效果**：自己 `-amount`、对方 `+amount`；**受赠者对赠送者关系 +2**
- **成功反馈示例**：`你送给 白夜 2个food，白夜 对你领情了`
- **失败反馈示例**：
  - `赠送对象不存在或已死亡`
  - `对方太远，没法赠送`
  - `只能赠送 food 或 ore`
  - `赠送数量至少为1`
  - `你的food不够`
- **日志 kind**：`trade`
- **日志示例**：`🎁 陈默 送给 白夜 2个food`
- **关系影响**：受赠者 → 赠送者 +2

调用示例：

```json
{ "action": "give", "args": { "target": "白夜", "item": "food", "amount": 2, "reason": "先送点吃的拉拢关系" } }
```

### `propose_trade(target, offer_item, offer_amount, want_item, want_amount)` — 提出交易

- **条件**：距离 ≤4；物品只支持 `food` / `ore`；数量 ≥1；自己有足够的出价物
- **限制**：对方已有待处理交易时失败（挂单不覆盖）
- **效果**：生成交易编号（`T回合-发起人id`），写入对方待处理交易
- **成功反馈示例**：`已向 白夜 提出交易`
- **失败反馈示例**：
  - `交易对象不存在`
  - `对方太远，没法交易`
  - `对方正在处理其他交易，稍后再试`
  - `交易数量无效`
  - `交易物品无效`
  - `你没有那么多food`
- **日志 kind**：`trade`
- **日志示例**：`🤝 陈默 向 白夜 提出交易：1个food 换 1个ore`
- **关系影响**：无（成交后才 +3）

调用示例：

```json
{ "action": "propose_trade", "args": { "target": "白夜", "offer_item": "food", "offer_amount": 1, "want_item": "ore", "want_amount": 1, "reason": "用多余食物换矿石做武器" } }
```

### `accept_trade(trade_id)` — 接受交易

- **复核**：接受时重新校验——对方存活、**双方距离仍 ≤4**（报价后走远则交易作废）、双方物品充足；任一不满足则取消挂单
- **效果**：双方物品互换，**双方关系各 +3**
- **成功反馈**：`交易完成`
- **失败反馈示例**：
  - `没有这笔交易`
  - `交易方已死亡`
  - `对方已走远，交易取消`
  - `你的东西不够，交易取消`
  - `对方的东西不够，交易取消`
- **日志 kind**：`trade`
- **日志示例**：`✅ 交易达成：白夜 用 1个ore 换到 1个food`
- **关系影响**：双方互相 +3

调用示例：

```json
{ "action": "accept_trade", "args": { "trade_id": "T5-0", "reason": "1换1很划算，成交" } }
```

### `decline_trade(trade_id)` — 拒绝交易

- **效果**：取消挂单；不影响关系分（但对方可能自己"记恨"）
- **成功反馈**：`你拒绝了交易`
- **失败反馈**：`没有这笔交易`
- **日志 kind**：`trade`
- **日志示例**：`❌ 白夜 拒绝了 陈默 的交易`
- **关系影响**：无

调用示例：

```json
{ "action": "decline_trade", "args": { "trade_id": "T5-0", "reason": "现在不需要食物" } }
```

## 心智

### `remember(note)` — 记笔记

- **效果**：写入长期笔记（上限 10 条，溢出丢最旧），每回合感知里可见；用于对抗短期记忆（见闻只留 12 条）
- **成功反馈**：`已记入长期笔记`
- **失败反馈**：`记了个寂寞`（空笔记）
- **日志 kind**：无
- **关系影响**：无

调用示例：

```json
{ "action": "remember", "args": { "note": "白夜连续两回合接近我，需警惕", "reason": "记录潜在威胁" } }
```

### `mark_ally(target)` — 宣布结盟

- **效果**：自己对目标的关系**提升为至少 +3**（已更高则不变）；全场公告
- **成功反馈示例**：`你宣布与 白夜 结盟`
- **失败反馈**：`目标不存在`
- **日志 kind**：`sys`
- **日志示例**：`🤜 陈默 宣布与 白夜 结为盟友！`
- **关系影响**：自己对目标 = max(当前值, 3)

调用示例：

```json
{ "action": "mark_ally", "args": { "target": "白夜", "reason": "白夜愿意交易，先结盟稳住" } }
```

### `mark_enemy(target)` — 宣布敌对

- **效果**：自己对目标的关系**降至 -3**（已更低则不变）；全场公告
- **成功反馈示例**：`你宣布与 白夜 敌对`
- **失败反馈**：`目标不存在`
- **日志 kind**：`sys`
- **日志示例**：`💢 陈默 宣布与 白夜 敌对！`
- **关系影响**：自己对目标 = min(当前值, -3)

调用示例：

```json
{ "action": "mark_enemy", "args": { "target": "白夜", "reason": "白夜刚才撒谎，划清界限" } }
```

## 关系分速查

| 档位 | 分数 |
|---|---|
| 盟友 | ≥ +3 |
| 友善 | +1 ~ +2 |
| 中立 | 0 |
| 敌对 | -1 ~ -4 |
| 深仇 | ≤ -5 |

改变途径：攻击（-4 / -6）、交易达成（双方 +3）、mark_ally（≥+3）、mark_enemy（≤-3）、上帝挑拨（两两 -5）。关系分无战斗数值加成，作用是写进提示词影响模型决策，并被演示模式 AI 用于威胁判断。

## 新增一个工具（开发者）

1. `TOOL_SCHEMAS` 加 function 定义（name/description/parameters）。
2. 写 `resolve_xxx(a, w, args, ctx)` 结算函数，返回 `(反馈, [(日志kind, 文本)])`。
